# Marketplace CRM

> Мониторинг публичной поисковой выдачи Wildberries, Ozon, Яндекс Маркета и Avito: задания из CRM, история цен, выгрузка CSV.

**Статус:** исходный код проекта. Работа с реальными сайтами и Docker-развёртывание не проверялись; перед коммерческим использованием необходимы приёмочные проверки и согласование доступа к данным с площадками.

## Возможности

| Направление | Что доступно |
| --- | --- |
| Мониторинги | Создание и редактирование поисковой фразы, площадок, числа страниц (1–10), интервала запуска; ручной запуск и пауза расписания |
| Сбор | Отдельный Playwright/Chromium-воркер, сохранение карточек по страницам, исключение дублей внутри запуска, журнал ошибок |
| Аналитика | История запусков, общее число собранных карточек и минимальная/максимальная цена по мониторингу, фильтр карточек по площадке |
| Экспорт | CSV отдельного задания и всей истории с защитой текстовых полей от формул в табличных редакторах |
| Доступ | Вход администратора, подписанная сессия и CSRF-защита форм; веб-сервис доступен только на `localhost` по умолчанию |

> Диапазон цен — сводка по **всем собранным карточкам всех запусков**, а не расчёт по уникальным товарам. Данные площадок могут быть неполными.

## Быстрый старт: Docker Compose

Нужны Docker Engine с Compose V2 и свободный порт `8000`. Сборка образа устанавливает Chromium и его системные зависимости: заранее предусмотрите место на диске и время загрузки.

```bash
cp .env.example .env
```

Отредактируйте `.env`, обязательно заменив `POSTGRES_PASSWORD`, `SECRET_KEY` (длинная случайная строка), `ADMIN_EMAIL` и `ADMIN_PASSWORD`. **Не публикуйте `.env` в Git.** Затем:

```bash
docker compose up --build -d
docker compose ps
docker compose logs -f web worker
```

Откройте **http://localhost:8000/login** и войдите с учётными данными из `.env`. Создайте мониторинг: первый запуск сразу ставится в очередь, затем (если задан интервал) запуски создаются автоматически. Детали ошибок и CSV доступны из истории заданий. Для остановки: `docker compose down` — данные БД сохраняются в volume `postgres_data`; **`docker compose down -v` удалит данные**.

### Настройка окружения

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL, используется и веб-сервисом, и воркером |
| `SECRET_KEY` | Ключ подписи браузерной сессии; замена завершит действующие сессии |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Создают администратора **только при первом запуске с пустой БД**; изменение переменных не меняет существующий пароль |
| `PAGE_DELAY_SECONDS` | Задержка между страницами, минимум 1 секунда, по умолчанию 3 |
| `BROWSER_PROXY_URL` | Необязательный HTTP(S)-прокси Chromium (например, корпоративный выход в нужном регионе) |
| `BROWSER_PROXY_USER`, `BROWSER_PROXY_PASSWORD` | Необязательная авторизация прокси |
| `COOKIE_SECURE=1` | Обязателен при внешнем доступе через HTTPS; браузер передаёт cookie только по HTTPS |

Для публикации в интернет настройте HTTPS и ограничение доступа на обратном прокси отдельно. В `compose.yaml` порт веб-сервиса привязан к `127.0.0.1`; не меняйте это без защиты периметра. Параметр `DATABASE_HOST` задаётся Compose автоматически; пароль PostgreSQL безопасно передаётся отдельно, поэтому спецсимволы в пароле допустимы.

### Обновление и резервное копирование

Перед обновлением создайте резервную копию:

```bash
docker compose exec -T db pg_dump -U marketplace marketplace > backup.sql
docker compose up --build -d
```

Храните `backup.sql` вне репозитория в защищённом месте. В проекте **нет полноценной системы миграций**: для полей снимка параметров задания есть совместимое обновление схемы при старте веб-сервиса; дальнейшие изменения схемы потребуют Alembic и отдельного плана миграции. Состояние сервисов: `docker compose ps`; проверка веб-сервиса: `http://localhost:8000/health`.

## Как работают задания

1. CRM создаёт мониторинг и задание со снимком его параметров. Редактирование мониторинга влияет только на **новые** задания.
2. Воркер забирает ожидающее задание из PostgreSQL, открывает страницы поиска через Chromium и сохраняет URL, заголовок, цену и изображение. Повторы URL внутри задания не сохраняются.
3. Статусы: `queued` → `running` → `done`, `partial` или `failed`. После перезапуска воркер повторно запускает прерванное задание; уже сохранённые URL пропускаются.
4. Отдельные проблемы страниц отображаются в деталях; при HTTP 403/429 или распознанной CAPTCHA обработка данной площадки прекращается до следующего запуска.

**Важно:** корпоративный прокси не гарантирует прохождение антибот-проверок. Универсального обхода CAPTCHA для всех площадок нет; сервис не решает CAPTCHA, не авторизуется на площадках и не использует закрытые API. Изменения HTML, региональные ограничения и условия использования могут влиять на выдачу. Для гарантированного доступа к коммерческим данным используйте официальные API или договоры.

## Структура проекта

```text
compose.yaml            PostgreSQL, веб-сервис и воркер
Dockerfile              Python и браузер Chromium
.env.example            образец обязательных настроек
app/db.py               модели БД и снимки параметров заданий
app/web.py              CRM, вход, обработчики, CSV
app/worker.py           планировщик и сбор результатов
app/templates/          интерфейс CRM
parser.py               адаптеры площадок и отдельный CLI
```

CLI для самостоятельной выгрузки после локальной установки зависимостей и Chromium: `python parser.py "офисное кресло" --sites wb ozon yandex avito --pages 2 --output results.csv`. Для проекта с CRM CLI не требуется.
